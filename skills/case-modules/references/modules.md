# Module specs

Each: **Method** → **Output** → **User decides**. Acceptance criteria come from btc-playbook
`references/deck-blocks.md`.

## users-and-jobs
Method: 3–5 candidate segments from research by **behaviour/context**, not demographics. For each:
job to be done (solution-free), current pain, **current workaround**, evidence link. Score on
stated criteria (pain severity, frequency, reachability, strategic fit). Flag any pain with no
workaround as "possibly not real".
Output: segment table + 2–3 personas. User decides: which persona to prioritise and the criterion.

## journey-and-pain
Method: stages across; rows = actions, touchpoints, emotion, pain points, **metric that detects
the problem at this stage**. Mark where the problem actually lives. For system behaviour, a
flowchart with decision nodes and failure paths.
Output: journey table. User decides: the 1–2 stages to attack.

## mvp
Method: separate **MVP vision** from **MVP formulation** (ships first / explicitly does not:
MoSCoW "Won't" list). Hypothesis: "We believe <change> will <effect> for <persona>; we're wrong if
<metric> stays below <threshold> after <time>."
Output: vision, formulation, won't-list, hypothesis. User decides: the cut line.

## prioritisation
Method: criteria first (derived from the case objective), weights stated, scores with sources.
Use RICE only with defensible reach/impact inputs; else impact/effort with labelled axes.
Output: scored table + ranking. User decides: accept or override (log the reason).

## metrics-stack
Method: btc-playbook `references/metrics-stack.md`. North Star, 2–4 inputs, outputs,
guardrails, counter-metrics, each with a target and timeframe; per side for multi-sided.
Output: metric tree table. User decides: the North Star and its target.

## economics
Method: unit economics (revenue per unit, variable costs, contribution), simple 3-year view if
the brief has a revenue target, break-even. Every input sourced or labelled; scenario low/base/high.
Output: assumptions table + summary; spreadsheet if > 5 linked numbers. User decides: base case.

## gtm
Method: the five GTM answers (who first and why; one-line positioning; channels with acquisition
economics; price + launch incentives; operational must-be-trues incl. supply side). Sequence named
cities/segments/partners with the reason for the order. Name exact places users are.
Output: GTM table + sequence. User decides: beachhead.

## right-to-win
Method: list the company's specific assets (data, distribution, relationships, infrastructure,
brand permission, cost position) and test each: would a well-funded entrant lack it? Keep only
assets that pass. Contrast with incumbents' advantages.
Output: assets table (asset → why entrants lack it → how the plan uses it). User decides: the 1–2
assets the strategy leans on.

## market-sizing
Method: TAM/SAM/SOM top-down AND bottom-up; reconcile; every figure sourced or estimated with
reasoning. Name direction (top-down vs bottom-up) and why.
Output: sizing table + reconciliation note. User decides: which number goes on the slide.

## options-and-rejection
Method: list the options the brief gives (or 3 plausible ones); criteria from the objective;
score; for every rejected option write the specific reason it lost. Check the chosen plan does not
quietly work for every option (hedging).
Output: options matrix + rejection lines. User decides: the bet.

## stakeholder-map
Method: every side (users, supply, partners, platform, regulators); what each wants, loses, can
block. Decide who you solve for and who you constrain; state what you are NOT doing.
Output: stakeholder table. User decides: primary side.

## root-cause
Method: confirm the problem is real (data/tracking changes?), external vs internal factors,
mechanism behind the symptom, Five Whys only to reach an insight. Precedents of the same
pathology elsewhere.
Output: cause tree with evidence. User decides: the cause to attack.

## governance
Method: rules, enforcement, escalation, appeal; who owns the metric; review cadence; abuse cases.
Output: governance table. User decides: enforcement strength.

## buyers-and-pricing
Method: product → buyer persona → willingness to pay → pricing model (cost-plus floor,
value-based, competitor-based; use at least two to bound a range) → packaging.
Output: chain table + price range. User decides: price point and model.

## roadmap-gates
Method: phases, each with a gate (metric + threshold) that must be true to proceed; timeframe
only as secondary.
Output: phase table. User decides: gate thresholds.

## risks
Method: 3–5 specific risks; each with mitigation and a leading indicator. No generic risks.
Output: risk table. User decides: which risk to show on the main deck vs appendix.
